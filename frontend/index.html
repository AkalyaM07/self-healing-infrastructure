G. About Project: Architecture & Technical Concepts

1. What is Self-Healing Infrastructure?

Self-healing infrastructure is an autonomous operations paradigm where systems continuously monitor their own health, detect faults (crashes, service outages, resource saturation), and apply automated remediation pipelines without requiring human operator intervention.

2. Role of Prometheus

Prometheus acts as the time-series metric aggregation engine. It actively scrapes endpoints (Node Exporter for CPU/RAM/Disk, and Blackbox Exporter for synthetic HTTP probing) at configured 5s intervals and evaluates alerting rules like NGINXDown in real time.

3. Role of Alertmanager

Alertmanager handles alert deduplication, grouping, rate-limiting, and smart routing. When NGINXDown fires, Alertmanager routes the payload to the FastAPI webhook receiver at /webhook/alerts while avoiding duplicate flap triggers.

4. Role of Ansible Automation

Ansible executes declarative, idempotent playbooks (restart_nginx.yml). It inspects container state, safely restarts the failed service, verifies container runtime status, and performs an HTTP health check before confirming the recovery.

5. The FastAPI Webhook Receiver

The Python FastAPI backend serves as the bridge between Alertmanager and Ansible. It validates the alert token, debounces duplicate requests, executes the playbook subprocess, logs outputs to SQLite, and updates the live web dashboard.

6. Blackbox Exporter Health Checks

Unlike internal metrics, Blackbox Exporter performs external synthetic testing (HTTP GET http://nginx:80). Even if an NGINX container is running, if it returns 502/503 errors or hangs, Blackbox detects the failure immediately.
